# ADR-0006 涨停棱镜页：涨停池 + 概念聚合 + 本地按日快照

日期：2026-11-07
状态：已采纳

## 背景

用户要求照经传多赢（n8n8.cn）的「涨停棱镜」在左侧导航加一页，功能与界面与源页面一致。
源页面四个面板：

1. **涨停周期表**：近 N 个交易日 × 每日涨停数 Top10 主题的网格，单元格右上角是该主题
   近 20 日涨停总数；
2. **涨停棱镜图**：黄线 = 沪深 A 股涨停总数、红色面积 = 所选主题涨停数；
   下方红色渐变条（0~3 / 3~5 / 5~10 / 10~15 / 15 以上）是**当日涨停家数**的色阶；
3. **主题榜**：主题的涨停数、涨幅、主力净买额、3 日/5 日主力、主力占比，带「热 / 扩张」标签；
4. **个股池**：炒作涨停 / 板块涨停 / 板块炸板 / 板块烂板 + 涨停原因、连板数、封板金额。

## 决策

### 1. 数据源：东财为主体，同花顺只补「涨停原因」

| 用途 | 接口 | 关键点 |
|---|---|---|
| 涨停池、炸板池 | `push2ex.eastmoney.com/getTopicZTPool` / `getTopicZBPool` | `tc` 总数、`lbc` 连板、`fund` 封单额、`zbc` 炸板次数、`hybk` 行业 |
| 概念板块 + 资金四列 | `push2/clist?fs=m:90 t:3` | `f3` 涨幅、`f62` 今日主力、`f184` 今日占比、`f267` 3 日主力、`f164` 5 日主力 |
| 个股所属概念 | `datacenter RPT_F10_CORETHEME_BOARDTYPE` | 每只涨停/炸板股 1 请求 |
| 涨停原因 | 同花顺 `dataapi/limit_up/limit_up_pool` 的 `reason_type` | 失败即降级为东财 `hybk` 行业名 |

**不让同花顺当主题维度**：它的概念代码（885xxx）与东财（BKxxxx）不同源，跨源做名称映射
既要维护别名表、又会污染资金列（资金只有东财给）。改成「东财概念 = 主题」后，
主题榜的资金四列天然同一套板块代码，不需要任何映射。

### 2. 概念归属必须用 `IS_PRECISE == "1"`

`RPT_F10_CORETHEME_BOARDTYPE` 返回的是「所属板块」大杂烩：行业、地域、财务特征、
东财特色数据（`最近多板` / `东方财富热股` / `连续亏损` / `QFII新进` / `基金减仓` …）全在里面。
只按「名字命中概念板块名单」过滤时，当日 Top1 会被 `最近多板`（12 家）、
`东方财富热股`（11 家）这种噪音霸榜。实测 `IS_PRECISE == "1"` 才是真正的精确概念
（每只票 4~16 个，全部命中概念名单；噪音项清一色是 `0` 或 `null`）。
名字黑名单只作为第二道保险（地域 `*板块`、`昨日*`、`*重仓`、财务特征）。

### 3. `clist` 的 `pz` 被上游截到 100，必须翻页

传 `pz=1000` 只回 100 条 —— 概念名单只剩前 100 个，导致 82 家涨停只落到 29 条归属、
主题全空。按 `pn` 翻到 `total`（531）为止。

### 4. 历史自建：每日快照 + 启动回补

东财涨停池的回溯窗口实测只有 **约 20 个自然日**（20261015 及更早一律空），
所以历史必须自己攒：每日收盘定稿写 `data/limitup.db`，启动时回补缺口，
**连续 3 个空日期即停**（再往前上游本来就没有）。
历史日期**不写资金四列** —— `clist` 给的是"当下"的钱，标到上周五头上是错的；
只有「最新交易日 + 数据日期 ≤ 4 天」时才补一次（覆盖周末/小长假）。

### 5. 口径近似（不是经传的专有算法，页面上不要当成结论）

- **主题等级**按**当日涨停家数**分档（0~3 / 3~5 / 5~10 / 10~15 / 15 以上），
  与色条一致；单元格右上角的数字才是近 20 日累计。
- **扩张** = 当日涨停数 > 前 5 日均值 × 1.5；
  **高潮** = 当日涨停数创近 20 日新高（且 ≥ 3 家）；
  **三共振** = 首板、连板、炸板三项同时高于各自前 5 日均值。
- **产业链 / 事件性 / 风格性** 按关键词近似归类（风格：高股息/低价/破净/次新/国资…；
  事件：业绩/涨价/中标/并购/政策…；其余归产业链）。
- **全市场涨停数**用东财 `tc`，与经传略有差异（同日实测 32 vs 33，ST/北交所口径）。

### 6. 采集节奏与自包含

`services/limitup.py` 完全自包含：只读写 `data/limitup.db`，不碰 `board_flow.db`，
不参与期权链路（与 `services/wangwang.py` 同一套路）。`app.py` 里
`asyncio.create_task(lu_svc.run_forever())`：盘中每 2 分钟刷当日，15:05 定稿锁定。

## 后果

- 新增一级导航「涨停棱镜」（`#/limitup`），侧栏图标 `Flame`。
- 接口 `/api/limitup/overview|prism|pool|health|refresh`，全部 `{error}` 降级不 500。
- 纯函数（分档、扩张/高潮/共振、矩阵构建、噪音过滤、主题聚合）在
  `tests/test_limitup.py`，不触网、不读时钟、不写盘。
- 页面是**浅色**主题（沿用项目 2026-10-13 起的浅色规范），只复刻信息结构。
- 已知局限：前 15~20 个交易日才有数据；主题体系是东财概念，会出现「央国企改革」这类
  宽泛主题靠前；涨停原因依赖同花顺，被 WAF 拦时显示行业名。
