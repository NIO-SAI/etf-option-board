# 持仓不做明细录入，改用敞口档位近似

看板的「组合 Greeks 纪律」与「临期风险」两项能力都依赖用户当前持仓。我们决定**不要求用户录入持仓明细**，而是用四档敞口档位（空仓 / 持有ETF / 持认购 / 持认沽）叠加三档规模（轻/中/重 = 总资金的 10% / 30% / 60%），缺失的 Greeks 用「当前优选合约」的 Greeks 近似填充。

取舍：牺牲组合 Greeks 的精度，换取零持仓录入负担与零持仓隐私风险——本仓库有 auto-backup 自动提交（现有 107 个提交全是快照），持仓金额一旦落盘就会进入 git 历史。总资金与单笔风险% 属必要输入，落在 `data/` 下被 `.gitignore` 忽略的 `.json` 中（注意现有规则忽略 `data/*.json` 却**不**忽略 `data/*.jsonl`，三个既有 jsonl 均已被 git 跟踪），不进 git 历史。

## Considered Options

- **手动录入持仓明细（后端持久化）**：能给出真实的 roll 候选与精确组合 Greeks，但需用户每日维护，且持仓金额会进本地 git 历史。
- **只存浏览器 IndexedDB**：无隐私外泄，但后端拿不到持仓，盘中告警与多到期扫描都要在前端重写——前端拿不到全链与多到期数据。
- **敞口档位（本决定）**。

## Consequences

- 组合 Greeks 是**估算值**，界面必须标明，不得呈现为真实敞口。
- 「移仓建议」这一能力被取消，替换为「到期日历 + 临期风险提醒」：不知道具体行权价与到期，roll 候选无法针对该腿。
- 单张风险、手数上限仍是精确的（由标的点位与合约价差算出），只有组合层是估算。
- 若日后要做卖方（备兑 / 卖沽），必须先决定「是否录入持仓明细」，即重开本 ADR。
