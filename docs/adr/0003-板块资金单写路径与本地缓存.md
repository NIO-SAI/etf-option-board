# ADR-0003 板块资金：采集器单写 SQLite + 只读接口 + 前端 SWR

日期：2026-11-04
状态：已采纳

## 背景

看板要从 `stock-webui` 移植「板块资金」四页（概念资金分时 / 主力资金多日图 / ETF资金流 /
东财资金分时）与板块详情抽屉。那套实现是「页面打开时现拉东财」，且历史数据靠另一个进程的
采集器写库。直接照搬会有两个问题：

1. 每次打开/切页都会触发上游批量请求，盘中频繁切换会打爆东财限流（本项目已有 `push2` 被接口级
   封禁的前车之鉴）；
2. 历史回看、名次变化、多日累计这些能力必须有持久化，而本项目此前只有 JSONL 形式的单标的累积。

## 决策

1. **单写路径**：板块/ETF 资金只由 `services/board_collector.py` 在交易时段写入
   `data/board_flow.db`（SQLite）；`routers/api.py` 的 `/api/board/*` 与 `/api/etf-flow/*`
   一律只读，绝不为了「页面有数据」回写或临时抓取。
2. **采集分频**（控制请求量）：板块排行 30s（约 11 个请求）、ETF 30s（69 只）、指数 4 维 30s、
   行业 4 维 60s（默认 Top40）。上一轮未完成则跳过，避免堆积。
3. **保留窗口**：分时点 30 天、排行快照 120 天，启动与每日各裁剪一次；写入按
   `(date, code, time)` 幂等 upsert。
4. **前端 SWR**：所有板块页走 `usePolling` + IndexedDB（`brank`/`bseries`/`bdetail`/`bmulti`/
   `etfrank`/`etfseries`/`emseries`），缓存比一个轮询周期新时首轮不发请求；盘中 30s、
   休市 300s、页面隐藏不请求。缓存容量 60MB，吃紧时**优先淘汰板块类**，保护期权上下文。
5. **接口聚合**：一页尽量一个请求（排行页一次取 `all`，切标签/排序纯本地；详情抽屉一次拿六块）。
6. **纯函数与 I/O 分离**：时段判定、解析归一、名次、区间聚合、序列对齐、裁剪计划都在
   `services/boardflow.py` 里做成纯函数并单测；存储层只做 SQL。

## 后果

- 打开板块页不再产生上游请求，切页接近零请求；代价是**服务重启后当天已过去的分钟无法回补**，
  与既有 `flow_history.jsonl` 的取舍一致，页面会明确提示「自启动起累积」。
- 多了一个常驻后台任务与一个 SQLite 文件（已 gitignore），但复用了现有 LaunchAgent 生命周期，
  没有新增守护进程。
- 行业 4 维默认只取 `|主力净流入|` 前 40（可配置），而不是 496 个含二三级行业的全量——
  全量会让一个轮询周期打 500 个请求，与「减少接口访问」直接冲突。

## 数据源踩坑（2026-11-04 实测）

- `emdatah5` 的 `fs=m:90+t:3` **必须把 `+` 编码成 `%2B`**；raw `+` 在 query 里等价空格，
  过滤条件会被忽略（返回 1113 条全板块，概念与行业混在一起）。`em._build` 的 `safe` 已去掉 `+`。
- 板块的 4 维资金 secid 必须是 `90.BKxxxx`，只传 `BKxxxx` 会全部失败并触发重试。
- `pz` 上限 100，概念板块 531 个、行业板块 496 个，翻页是必须的。
