# 板块资金看板移植规格（PRD）

Status: ready-for-agent
Type: feature
来源会话: 2026-11-04，移植 `stock-webui` 的「板块资金」四个页面到 ETF 期权看板，并用 REUI 重写。

## Problem Statement

我现在只能在 `stock-webui`（6688，Jinja2 + Metronic）里看板块资金，做期权决策时要另开一个站点、另学一套交互：
页面风格是浅色 Bootstrap，跟期权看板的深色 REUI 完全割裂；换页、切板块、回看历史都要重新请求后端，
盘中切来切去很慢；而且那套前端的筛选、排序、自选、历史回看分散在多个页面，想「板块资金 ↔ 期权标的」对照着看
必须来回切浏览器标签。

## Solution

在 ETF 期权看板左上角加一排页面切换标签，把 `stock-webui` 的「板块资金」四页整体搬进本项目：

1. **概念资金分时** —— 概念/行业板块资金排行 + 选中板块当日分时曲线 + 自选板块 + 历史日期回看。
2. **主力资金多日图** —— 任选日期区间，多板块资金流走势对比 / 排行。
3. **ETF资金流** —— ETF 资金流排行 + 分时曲线 + 4 维资金拆解（9 只期权标的必在其中）。
4. **东财资金分时** —— 行业板块 / 核心指数 / 全 A 的机构、大单、中户、散户 4 维资金分时。

功能对齐 stock-webui，交互与视觉用本项目现有的 REUI 深色看板语言重写：`Frame/FrameHeader/FramePanel`
卡片、ECharts 图表、`Fold` 折叠、`Tip`、`Badge`、`Skeleton/EmptyState`。

数据不再是「每次打开页面去东财拉」，而是**本项目自建采集器**在交易时段写入本地 SQLite，
读接口只读库；前端所有页面走 IndexedDB stale-while-revalidate：进页面先渲染上次的数据，
后台静默刷新，切页/切板块几乎不产生请求。

## User Stories

1. 作为期权交易者，我想在看板左上角看到一排页面标签，这样我不用换站点就能切到板块资金。
2. 作为期权交易者，我想当前所在页面的标签高亮，这样我知道自己在哪一页。
3. 作为期权交易者，我想刷新浏览器后仍停留在原来的页面标签，而不是被弹回期权看板。
4. 作为期权交易者，我想直接分享一个板块资金页面的链接，这样我能把某个板块发给别人看。
5. 作为期权交易者，我想在「概念资金分时」看到按主力净流入排序的板块列表，这样我能看出今天的主线。
6. 作为期权交易者，我想在概念/行业之间切换排行口径，这样我能区分题材炒作与行业景气。
7. 作为期权交易者，我想按主力净流入、涨跌幅、成交额等字段点表头排序，这样我能换角度看资金。
8. 作为期权交易者，我想一眼看出每个板块的主力净流入是红是绿、金额与涨跌幅并列，这样不用点开就知道强弱。
9. 作为期权交易者，我想同时看到排行前 N 个板块的当日资金分时曲线，这样我能比较谁的资金是持续流入。
10. 作为期权交易者，我想鼠标悬停时看到该时间点的各板块资金数值，这样能定位异动时刻。

13. 作为期权交易者，我想在详情里看到板块成分股的资金排行，这样我能找到板块内的龙头。

30. 作为期权交易者，我想在 ETF 页看到 4 维资金（机构/大单/中户/散户）拆解，这样我知道是谁在买。
31. 作为期权交易者，我想在 ETF 页看到自选 ETF，这样我能盯住几个核心品种。
32. 作为期权交易者，我想在「东财资金分时」看到行业板块的 4 维资金分时，这样我能看行业内部结构。
33. 作为期权交易者，我想在「东财资金分时」切换核心指数与全 A 聚合，这样我能看大盘整体资金结构。
34. 作为期权交易者，我想在「东财资金分时」看到各维度堆叠/分线的图，这样我能读出动能与散户的对手盘。
35. 作为期权交易者，我想头部只保留最少的一排控件（日期、排序、图线开关），这样图表占满屏。
36. 作为期权交易者，我想所有页面在数据到达前显示骨架而不是空白，这样我知道它在加载。
37. 作为期权交易者，我想所有页面在接口失败时显示「降级/无数据」提示而不是报错白屏，这样我能继续用其它页。
38. 作为期权交易者，我想切回已看过的页面时立刻有内容（本地缓存），这样盘中切换不卡顿。
39. 作为期权交易者，我想页面切到后台时停止轮询，这样不浪费请求、不拖慢其它标签页。
40. 作为期权交易者，我想盘中数据 30 秒级刷新、非交易时段不再频繁请求，这样数据够新又不打爆接口。
41. 作为运维者（我自己），我想采集器随主进程启动、随 LaunchAgent 自动恢复，这样我不需要多配一个守护进程。
42. 作为运维者，我想采集只在工作日交易时段进行，这样收盘后不空转、不请求。
43. 作为运维者，我想数据库自动裁剪过期数据（分时 30 天、排行 120 天），这样磁盘不会一直涨。
44. 作为运维者，我想采集失败只记日志、不影响告警链路与期权看板，这样板块功能挂了也不耽误交易。
45. 作为运维者，我想采集器一轮没跑完就跳过下一轮，这样不会堆积并发请求。
46. 作为运维者，我想看采集器是否在跑、最后一轮写到哪个时间，这样能快速定位「页面没数据」。
47. 作为运维者，我想板块功能新增的接口失败时返回 `{error}` 而不是 500，这样与现有 API 约定一致。
48. 作为开发者，我想板块数据的解析、归一、裁剪、交易时段判定都是纯函数，这样我能离线单测，不用触网读时钟。
49. 作为开发者，我想新页面复用现有 `Frame` 卡片与 `usePolling` + IndexedDB 缓存，这样风格与代码路径统一。
50. 作为开发者，我想把「一页所需数据」合并成尽量少的接口，这样前端不用一次打十几个请求。

## Implementation Decisions

### 范围与产品边界

- 四页 + 板块详情抽屉。详情是抽屉（右侧滑出），不是独立路由页。
- 板块类型只做 **概念 + 行业 + 自选**，不采集也不展示「地区」（UI 不出现无效标签）。
- 保留：自选板块（后端 JSON 持久化）、历史日期回看、简化的「最后更新时间 / 交易中」标记。
- 不做：stock-webui 的看板全景图（all-flows panorama）、复杂 health 探测面板、平安/网宿等第三方资金源。
- ETF 资金流页**独立实现**，不耦合期权看板已有的 ETF 行情接口；采集范围收敛为
  **9 只期权标的 + 宽基（成交额 Top30）+ 行业 ETF（Top30）**，不照搬全市场 ~670 只。

### 数据与单一写路径（ADR-0003）

- 新增 `services/boardflow.py`：唯一的板块资金 SQLite 存储层（路径 `data/board_flow.db`，
  已被 `data/*.db` 规则忽略，需补 `.gitignore`）。表结构沿用 stock-webui 的 flowdb 精简版：
  `boards(code,name,type)`、`flow_points(date,code,time,flow)`、`rank_snapshots(date,code,name,type,flow,pct)`、
  `etf_boards`、`etf_flow_points`、`etf_rank_snapshots`、`em_flow_points(date,code,time,inst,large,medium,retail)`。
- **单写者**：只有采集循环写库；所有读接口只读，绝不回写。
- 连接管理照搬 stock-webui 的教训：每次操作加锁打开连接、显式 `close()`（避免 fd 泄漏），`WAL` 模式。
- 读接口失败/库为空时的降级：返回 `{error}` 或空列表 + `stale` 标记，由前端展示骨架/空态；
  不为了「有数据」而实时打东财（避免把页面打开变成一次批量请求）。
- 保留窗口：分时点 30 个交易日、排行快照 120 个交易日，启动时 + 每日首轮采集后各裁剪一次。

### 采集器

- 新增 `services/collectord.py`：随 FastAPI lifespan 起的 asyncio 后台任务，跟 `monitor.run_forever()` 并列，
  异常只记日志（`log.warning`），任何异常都不得影响 monitor/告警。
- 交易时段判定（工作日 09:30–11:30 / 13:00–15:00）做成**注入当前时间的纯函数**，可单测。
- 分频（按数据源，控制请求量）：
  - 板块排行 f62（概念 + 行业，约 6 个请求/轮）：**30s**
  - ETF 资金流排行/分时（9 + Top30 + Top30，约 70 个请求/轮）：**30s**（并发上限 8，失败只跳过）
  - 指数 4 维（9 个指数 + 全 A 聚合）：**30s**
  - 行业 4 维（约 86 个 BK）：**60s**
- 每轮「上一轮未跑完则跳过」，避免堆积；写入按 `(date, code, time)` 幂等 upsert，
  同一分钟重复采集只更新不产生重复行。
- 采集入口也在 `services/em.py` 里（保持「唯一网络出口」约定）：新增
  `board_rank_rows(fs, ...)`（一次拉全量排行，内部翻页）与 `board_four_dim(secid)`（4 维快照）。

### HTTP 接口契约（前缀统一，避免与现有 `/api/etf/{code}` 冲突）

每页尽量一个聚合接口，减少往返：

- `GET /api/board/health` → `{trading, last_time, last_date, boards, points}`（采集状态）
- `GET /api/board/rank?type=concept|industry|watch&date=` → 排行（含 `pct`、`flow`、`rank_delta`）
- `GET /api/board/series?codes=BK1,BK2&date=` → 多板块当日资金分时（对齐后的序列）
- `GET /api/board/dates?limit=60` → 可回看的日期列表
- `GET /api/board/multi?start=&end=&type=` → 区间累计排行 + Top N 累计序列（一页一次）
- `GET /api/board/detail?code=&date=` → **详情抽屉一次拿全**：当日分时、成分股资金、主力增量、
  近 20 日历史、对标指数序列、研报热度（各块失败互相独立，缺失用 `null`）
- `GET/POST/DELETE /api/board/watch` → 自选板块（读写 `data/board_watch.json`）
- `GET /api/etf-flow/rank?scope=all|hot|watch&date=`、`GET /api/etf-flow/series?codes=&date=`、
  `GET /api/etf-flow/4dim?code=`、`GET/POST/DELETE /api/etf-flow/watch`
- `GET /api/em-flow/industries`、`GET /api/em-flow/series?target_type=index|industry|market&code=`、
  `GET /api/em-flow/config`（行业展示 Top20 配置，持久化 JSON）

### 前端

- **导航**：一排扁平标签（期权看板 / 概念资金分时 / 主力资金多日图 / ETF资金流 / 东财资金分时），
  放左上角、位于现有 `TopBar` 同一行左侧；hash 路由（`#/options`、`#/board/flow`、`#/board/multi`、
  `#/board/etf`、`#/board/em`），不引入 react-router；刷新保持当前页，可复制链接。
- **页面外壳**：`web/src/App.tsx` 只做路由分发；四个页面各自 `web/src/pages/*.tsx`，复用
  `Frame/FrameHeader/FramePanel/FrameTitle`、`Badge`、`Fold`、`Tip`、`Skeleton/EmptyState`、ECharts 封装。
- **缓存**：扩展 `web/src/lib/cache.ts` 的 `CacheKind`（`board-rank` / `board-series` / `board-detail` /
  `board-multi` / `etf-rank` / `etf-series` / `em-series`），全部走 `usePolling` 的 SWR；
  缓存比一个轮询周期新时首轮不发请求；跨日失效（`health`/`dates` 等元数据跨日保留）。
- **轮询频率**：盘中 30s（4 维 60s 的页面对齐 60s）、非交易时段 300s、页面隐藏时不请求。
- **交互**：排行表支持点表头排序与「只看自选」；板块行点击开右侧抽屉；抽屉内六个块各自有加载/空态；
  图表提供图线开关（常驻，数据没到只置灰，避免布局跳动——沿用现有约定）。
- **视觉**：深色 `Frame` 卡片、红涨绿跌沿用 `lib/format.ts` 的 `clsUpDown`/`pct`/`signedWan`；
  不引入新的 UI 依赖。

## Testing Decisions

- **只测纯函数**，与现有 `tests/` 一致：不触网、不读系统时钟、不写磁盘（日期/时间全部注入）。
- 被测模块：`services/boardflow.py` 的纯函数部分——
  - 交易时段判定（含周末、11:30/13:00 边界、午休、非交易日）；
  - 排行解析与归一（东财 `f12/f14/f62/f3` → 内部结构，缺字段/坏值丢弃而不是抛异）；
  - 排行差分（`rank_delta`：与上一轮名次比较，新增/消失的板块不产生脏数据）；
  - 保留窗口裁剪计划（给定今日与保留天数 → 应删除的 `date` 列表），只断言计划，不落盘；
  - 多板块序列按时间轴对齐（前值填充 + 同日校验），复刻前端 `series.ts` 的口径，避免前后端口径漂移。
- 测的是**外部可观察行为**（输入 → 输出），不测 SQL 语句与私有实现。
- 先例：`tests/test_expiry.py`（日期注入）、`tests/test_levels.py`（数值归一）、`tests/test_user_settings.py`（配置读写容错）。
- HTTP 层与前端不做自动化测试：沿用 `curl /api/board/health` 冒烟 + 浏览器核对（含向多设备经 Tailscale 访问）。

## Out of Scope

- 「地区」板块类型（不采集、不展示）。
- stock-webui 的「看板全景图」「多日百分比涨幅图」「研报热度子站」「平安行业资金流」等附属模块。
- 全市场 ~670 只 ETF 的全量采集。
- 改动 stock-webui 本身；两个项目的数据互不依赖。
- 期权看板现有页面的功能/布局重构（只加标签与路由分发）。
- 把板块资金接入告警/信号引擎（本期只做看板呈现）。

## Further Notes

- 真实数据源结论（沿用本项目既有经验）：板块排行与 4 维资金都走 **emdatah5**（`getZDYLBData` /
  `getZJLXData`）；`push2 clist` 在本机已被接口级封禁，只作兜底。K 线/分时仍走腾讯。
- 采集器写库与页面读库解耦，意味着「服务重启后当天已过去的分钟无法回补」——这与现有
  `flow_history.jsonl` 的既有取舍一致；文档里要写明，避免被当成 bug。
- 现有 `web/src/lib/cache.ts` 的容量上限 20MB；板块四页 + 详情的数据量更大，需要把上限提到
  ~60MB 并对 `board-*` 类做「只保留最近 3 个交易日」的软淘汰，避免把期权上下文的缓存挤掉。
- 若后续要求盘中 10s 级刷新，只需调采集分频与前端轮询，不改接口契约。
